# LogLens v0.4.0 — Portfolio-ready hardening

LogLens v0.4.0 packages the defensive-analysis hardening completed after v0.3.0 into a coherent portfolio release candidate.

## Highlights

- safer analyst message filtering through Unicode compatibility normalization and invisible-format handling
- canonical source identities with preserved structural boundaries to reduce accidental source collisions
- source-aware anomaly detection and health summaries for multi-service logs
- broader defensive ingestion support, including OpenTelemetry/ECS-style JSON, journald JSON, RFC 5424, stdin, and local gzip logs
- explicit parse-error budgets and CI-friendly finding severity gates
- deterministic JSON/CSV reporting with effective detection configuration and time-window context
- reproducible local portfolio demo with no network or offensive behavior

## Release validation

Before tagging `v0.4.0`:

1. CI must pass on every supported Python version.
2. The package version and `loglens --version` must both report `0.4.0`.
3. The portfolio demo should remain reproducible from a clean checkout.
4. No open correctness or security-regression issue should remain unresolved.

This release remains intentionally defensive: findings are explainable triage signals, not incident verdicts, and LogLens does not provide exploitation, credential theft, persistence, or offensive payload functionality.
