# RFC 5424 syslog analysis

LogLens can analyze RFC 5424 syslog records explicitly with the strict parser:

```bash
loglens analyze /var/log/forwarded.log --format rfc5424
loglens analyze /var/log/forwarded.log --format rfc5424 --source sshd --json
```

The parser normalizes PRI severity, timestamp, and logical source while retaining common syslog header metadata. `APP-NAME` is preferred as the logical source, followed by hostname and then input provenance when RFC 5424 uses NILVALUE (`-`).

Strict mode is intentional: malformed RFC 5424 records count as parse errors instead of being silently reinterpreted as generic text. The normal `--max-parse-errors N` budget can be used when an analyst expects a bounded amount of known input noise.

Automatic mode remains conservative and does not guess that arbitrary text is RFC 5424. Use `--format rfc5424` when the input contract is known. This keeps parsing deterministic and makes malformed telemetry visible in reports and exit status.
